# 機能仕様

## 1. 用語

| 用語 | 意味 |
|------|------|
| ポスト詳細 | 単一ポストを主表示とし、返信スレッド等が続く画面。 |
| 偽リプ | 本拡張が DOM に追加する、実際の X 上のリプライではない表示要素。 |
| インプレゾンビ風 | 浅い称賛・テンプレ感・絵文字多め等、インプレッション目的のリプに似たトーン（プロンプトで制御）。 |
| プリセット | 拡張バンドル内の固定文言リスト。API 非使用時およびフォールバック用。 |

## 2. 対象 URL

- **有効パス（例）**: `https://x.com/*/status/*`  
- **互換**: `https://twitter.com/*/status/*` を同一挙動で扱うかは実装フェーズで決定（推奨: 併記）。
- 上記以外の URL では、本機能のコンテンツスクリプトは**原則ロードしない**（`matches` で制限）。

## 3. 拡張の ON/OFF

- 利用者が **オフ**にしたとき: 偽リプを挿入・再挿入しない。既に挿入済みのノードは除去するか、ページリロードで自然消滅するかは実装で定義（推奨: オフ時に除去＋オブザーバ停止）。
- **オン**のときのみ、以下の挙動を行う。

## 4. 偽リプの生成ロジック

### 4.1 優先順位

1. **LLM モードが有効**かつ API キー（および必要ならベース URL）が設定されている場合  
   - 元ポストの**本文テキスト**を入力の主材料とし、指定トーンで複数件の短文を生成する。  
   - 出力形式は **機械可読（例: JSON の配列）** を推奨し、パース失敗時は 4.3 へ。
2. 上記以外、または API エラー・タイムアウト・レート制限・パース失敗時  
   - **プリセット**から必要件数を選ぶ。**選定とキャッシュ書き込みは Service Worker** が行い、コンテンツスクリプトは返却された文字列配列を表示する。

### 4.2 元ポスト本文の取得

- コンテンツスクリプトが DOM から抽出する。  
- **取得失敗時**: 空本文として LLM に渡すか、直接プリセットにフォールバックするかを設定で選べるようにするか、仕様として「空ならプリセット固定」と単純化してよい。

### 4.3 プリセット仕様

- 拡張に同梱する **文字列配列**（件数・内容は実装時に定義）。  
- トピックをばらけさせ、**元ポストと無関係でもそれっぽい**一文として成立する文言を混ぜる。

### 4.4 キャッシュ（推奨仕様）

- **キー**: 正規化したポスト詳細 URL（クエリはポスト識別に不要なら除去）。  
- **値**: 生成済み偽リプのテキスト配列、生成時刻。  
- **同一セッションまたは `chrome.storage.local`**: 再訪問時に API を再叩かない既定 TTL（例: 24 時間）を設けてもよい。
- **件数不足時の補完**: キャッシュに保存された行数が、利用者が指定した偽リプ件数に満たない場合は **プリセットで不足分を追加**し、同一キーのキャッシュを更新してよい（実装）。

### 5.1 挿入位置（実装）

- **アンカー**: `main` 内の**先頭** `article`（詳細ページでは主ポストの行に相当することが多い）を基準に、その**直後**に拡張ルートを挿入する。  
- **ルートノード**: `section` に一意属性 `data-zombie-sim-root` を付与し、再挿入の idempotency と `MutationObserver` 判定に用いる。

### 5.2 偽リプ行の DOM（公式に寄せる方針）

本拡張は、X がポスト行で用いる **DOM の階層・役割**に意図的に寄せる（画面上は公式リプに近い読み方になることを目標とする）。

| 公式側の概念（参考） | 拡張が生成するノード |
|----------------------|----------------------|
| `div[data-testid="cellInnerDiv"]` に相当する行コンテナ | `div.zombie-sim-cell`（`data-zombie-sim-cell`） |
| 行内ラッパー | `div.zombie-sim-cellInner` |
| `article[data-testid="tweet"]` に相当するポスト単位 | `article.zombie-sim-tweetArticle`（`data-zombie-sim-tweet`）※`data-testid="tweet"` は**付与しない**（公式ノード・スクリプトとの衝突を避ける） |
| 左アバター列（40×40 相当） | `div.zombie-sim-avatarRail` → `zombie-sim-avatarHost` → `zombie-sim-avatar` |
| `User-Name` 行（表示名・@・区切り・メタ） | `div.zombie-sim-userName`（`data-zombie-sim-user-name`）内の `zombie-sim-userNameRow` および子 `span` |
| 認証バッジ（任意表示） | `svg.zombie-sim-verifiedSvg`（公式に近い path、行インデックス等で出し分け） |
| 投稿日時相当 | `span.zombie-sim-timeWrap` 内の `<time datetime="ISO8601">`（相対・「昨日」・「M月D日」等をローカル生成） |
| `tweetText` に相当する本文 | `div.zombie-sim-tweetText`（`data-zombie-sim-tweet-text`、`dir="auto"`、`lang="ja"`） |
| 返信／RT／いいね／表示／ブクマ／共有のツールバー | `div.zombie-sim-actions` → `div.zombie-sim-actionRow`（`role="group"`）内の `button.zombie-sim-actionBtn` と SVG（`data-testid` は付与しない） |

**スタイル**: `extension/styles/content.css` に **接頭辞 `zombie-sim-`** のクラスで定義する。X の **ハッシュ／ユーティリティクラス**（例: `r-*`, `css-*`）には**依存しない**（変更頻度が高く保守不能なため）。色・字組・行高は、ダーク／ライトで公式に近いトークン（例: 本文 `#e7e9ea` / 補助 `#71767b` 系）を CSS 変数で切り替える。

**テーマ（ダーク／ライト）**: ページ上の **`[data-testid="tweetText"]` の算出 `color`** を優先して輝度判定し、拡張ルートに `zombie-sim-root--dark` / `zombie-sim-root--light` を付与する。判定不能時は `primaryColumn` / `main` / `body` の背景色と `prefers-color-scheme` にフォールバックする。

**セキュリティ**: 生成テキストは **`textContent` のみ**で挿入し、公式と同様に XSS を避ける（`innerHTML` 禁止）。

### 5.3 元ポスト本文の抽出セレクタ（読み取り専用）

- **優先**: `main article[data-testid="tweet"]` 内の最初の `[data-testid="tweetText"]`。  
- **フォールバック**: `main [data-testid="tweetText"]`。  
- 上記は **ページからの読み取り**にのみ用い、拡張が生成する偽ノードに `data-testid="tweet"` を重ねてはならない。

### 5.4 再挿入（MutationObserver）

- X の再レンダリングで偽ノードが削除された場合: **`MutationObserver`**（または同等）で検知し、**同一内容で再挿入**する。  
- **監視**: `main` 配下の subtree（広すぎる `document.body` 一括監視は避ける）。  
- **無限ループ防止**: デバウンス（実装では数百 ms 程度）および、同一ウィンドウ内での **メッセージ再試行上限**（例: 1 分あたり N 回）を設ける。異常時はオブザーバを停止する。

## 6. 更新抑止（任意・フェーズ 2）

- 必須ではない。導入する場合の仕様案:  
  - **`declarativeNetRequest`**: 拡張 ON 時のみ、既知パターンの **ライブ更新系** リクエストをブロック。  
  - または **MAIN ワールド**で `fetch` / `WebSocket` を限定的にラップ（メンテナンスコスト高）。  
- ブロック対象は **ホワイトリスト的に狭く**定義し、初回ロードに必要な通信は壊さないことを前提に検証する。

## 7. 設定（オプション UI）

| 項目 | 説明 |
|------|------|
| LLM 有効/無効 | トグル。 |
| API キー | `password` 入力。`chrome.storage.local` 保存。 |
| API ベース URL（任意） | OpenAI 互換プロキシ等。 |
| モデル名（任意） | 既定モデルをドキュメント化。 |
| 偽リプ件数 | 表示数の上限・既定値。 |
| （任意）空本文時の挙動 | LLM 試行 / 即プリセット。 |

## 8. 権限（manifest 想定）

- `storage`（設定・キャッシュ）  
- `host_permissions`: `https://x.com/*`、必要なら `https://twitter.com/*`  
- コンテンツスクリプトの `matches` を上記 URL パターンに限定  
- フェーズ 2 で DNR を使う場合: `declarativeNetRequest` および `declarativeNetRequestFeedback` 等、必要最小限の権限

## 9. 受け入れ基準（初期リリース目安）

- ポスト詳細でオン時のみ偽リプが表示される。  
- 偽リプ行の DOM は **§5.2** に従い公式ポスト行に寄せ、ダーク／ライトでタイムラインと著しく色が食い違わないこと。  
- オフで挿入が止まり、可能なら既存偽ノードが消える。  
- API 未設定時にプリセットのみで動作する。  
- API 失敗時にプリセットへ落ちる。  
- LLM 由来テキストが HTML として解釈されず表示される。  
- スクロールや内部更新後も、**一定時間内**は偽リプが復帰する（Observer 動作）。

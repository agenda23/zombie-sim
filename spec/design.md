# 技術設計

## 1. アーキテクチャ概要

```
┌─────────────────────────────────────────────────────────┐
│ Chrome 拡張 (Manifest V3)                                │
├─────────────────┬───────────────────┬───────────────────┤
│ Options UI      │ Service Worker    │ Content Script    │
│ (options.html)  │ (background.js)   │ (detail ページのみ)│
│ 設定入力        │ LLM HTTP 呼出     │ DOM 抽出・挿入     │
│ storage 読書き  │ 秘密の保持        │ MutationObserver   │
└────────┬────────┴─────────┬─────────┴──────────┬────────┘
         │                  │                    │
         └────────── chrome.storage.local ───────┘
                            │
                     ┌──────▼──────┐
                     │ LLM API     │ (利用者指定、HTTPS)
                     │ (外部)      │
                     └─────────────┘
```

- **Service Worker**: LLM への `fetch` を実行。ページの CORS に依存せず、API キーをコンテンツスクリプトに渡さない。  
- **Content Script**: 元ポスト本文の抽出、偽リプ DOM の生成・挿入、`MutationObserver` の管理。  
- **Options**: API キー・トグル・件数等。`chrome.storage.local` に永続化。

## 2. メッセージング

| 方向 | メッセージ例 | ペイロード概要 |
|------|----------------|----------------|
| CS → SW | `GENERATE_REPLIES` | 本文テキスト、希望件数、設定参照フラグ |
| SW → CS | 同上の応答 | 文字列配列（`ok: true`）または無効化コード（`ok: false` / `DISABLED`）。プリセット経路も `ok: true` で返す。 |
| CS 内部 | （オプション）キャッシュヒット時は SW を呼ばない | URL キーで `storage` 参照 |

- 長文本文は **切り詰め**（トークン上限）してから送信する。  
- LLM 未使用・失敗・パース失敗時は **SW がプリセット文字列を選び**、可能なら **キャッシュに保存したうえで** 文字列配列を返す（CS は表示のみ）。仕様書 4.1 と整合。

## 3. DOM 戦略（合意: 「次点」）

### 3.1 挿入

- ポスト詳細レイアウトにおける **会話ツリーのコンテナ**を特定し、その**直後または専用ラッパ**内に偽リプリストを挿入する。  
- 偽リプルートには **一意の `data-*` 属性**（例: `data-zombie-sim-root`）を付与し、Observer の判定と再挿入の idempotency に使う。

### 3.2 再挿入（MutationObserver）

- **監視対象**: 挿入親の近傍、または `main` 配下の狭い subtree（パフォーマンスのため広すぎる `document.body` 一括監視は避ける）。  
- **トリガー**: 自前ルートが DOM から外れた、または子が空になった等。  
- **対策**: `requestAnimationFrame` または `setTimeout(0)` で **デバウンス**し、連続再配置でのループを防ぐ。  
- **最大再試行回数**（例: 同一 URL で 1 分間に N 回まで）を設け、異常時はオブザーバ停止＋ユーザー通知（バッジ or console）を検討。

### 3.3 スタイル（公式 DOM/CSS に寄せる）

- **方針**: X のポスト行と **同型の DOM 階層**（`cellInnerDiv` 相当 → `article` → 左アバター列 + 右本文列、`User-Name` 行、`tweetText` 相当）を **自前の接頭辞付きクラス／`data-zombie-sim-*`** で再現する。タイポグラフィ・余白・境界線・ダーク／ライトの色トークンは **公式に近い値**を `content.css` の CSS 変数で持つ。  
- **依存しないもの**: X の **ハッシュ付きクラス**（`r-*`, `css-*` 等）には依存しない（更新で即死するため）。  
- **読み取り専用の例外**: ページからの抽出・テーマ推定には、比較的安定な **`data-testid`（例: `tweet`, `tweetText`）** を用いてよい（抽出ロジックは `content.ts` 内の関数に集約）。  
- **Shadow DOM**: 採用しない（現行実装）。グローバル `content.css` と接頭辞クラスで衝突を避ける。  
- 詳細な要素対応表は **specification.md §5.2** を正とする。

## 4. LLM 連携

### 4.1 リクエスト

- SW が `POST` でチャット補完 API（実装時にプロバイダ固定 or 互換レイヤーを選択）。  
- システムプロンプトで **日本語・短文・インプレゾンビ風・元ポストへの言及**を指示。  
- レスポンスは **JSON**（例: `{ "replies": ["...", "..."] }`）を契約とし、パースライブラリは最小限。

### 4.2 セキュリティ

- API キーは **Options → `chrome.storage.local` のみ**。SW は `chrome.storage` API で読み取る。  
- ログに本文・キーを出さない。

## 5. プリセット

- `presets.json` または `presets.ts` としてバンドル。  
- Fisher–Yates シャッフルまたは重み付きランダムで重複を減らす。

## 6. 更新抑止（フェーズ 2・任意）

| 手段 | 長所 | 短所 |
|------|------|------|
| `declarativeNetRequest` | SW から動的 ON/OFF、キーをページに出さない | URL パターンのメンテ |
| MAIN `fetch` / `WebSocket` ラップ | 細かい条件 | 壊れやすい、注入タイミングが難しい |

- 初回は **未実装**でもよい。設計上のフックとして「SW が `declarativeNetRequest.updateDynamicRules` を呼べる」状態を権限設計にだけ残す選択可。

## 7. リスクと緩和

| リスク | 緩和 |
|--------|------|
| X の DOM 変更でセレクタ破損 | **読み取り**用セレクタは `content.ts` の抽出関数に集約。偽ノードは公式 `r-*` / `css-*` に依存しないため、見た目は接頭辞 CSS の更新で追随。失敗時は挿入スキップ／ユーザー向け「要更新」 |
| Observer ループ | デバウンス、再試行上限、自ノード変更の無視 |
| LLM コスト・レート | キャッシュ、件数上限、デバウンスした再生成禁止 |
| XSS | `textContent`、構造化は `createElement` で組み立て |

## 8. ディレクトリ構成案（実装フェーズ）

```
extension/
  manifest.json
  src/
    background.ts      # SW
    content.ts         # CS
    options.ts
    presets.ts
    types.ts
  options.html
  styles/
    content.css
```

（実際のパス・ビルドツールはリポジトリ方針に合わせて変更する。）

## 9. 将来拡張（本設計では必須としない）

- **独立オーバーレイレイヤー**: `body` 直下の固定パネルに偽リプのみ表示し、X のツリー更新と分離。安定性は高いが UX が「公式に混ざる」とは異なる。  
- **全面ネットワークブロック**: メンテコストと破損リスクが高いため採用しない。

## 10. 変更管理

- DOM セレクタや API エンドポイント契約を変えたら **specification.md** の該当節と同期する。  
- 権限を増やしたら **requirements.md** の非機能・コンプライアンスを見直す。
